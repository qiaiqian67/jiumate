> **DRAFT — 用户输入需求(进行中)**。这块**不在页面权威盘点之内**:用户当面提出的、还没进入空白分析或决策表的产品需求草稿。等正式立项时按工程拆分进对应子节、决策表、路线图,然后本节删除。状态由用户口述驱动,可能互斥、可能重复、可能不完整 —— 用户已声明"后面还有"。

## M. 会话确认的实时提醒

需求:会话中有需要人类确认的事项(典型:approval 等待 —— 工具执行前审批、超时未回),**主动推一个消息提醒**给用户,不依赖用户盯着 UI。

触发场景:

- Agent 触发 `approval_mode != "allow-all"` 的工具,等待人类决定
- 已发出的 approval 超时阈值
- 其他需要人工介入的状态(任务失败、token 烧光、外部服务报错等)

| 需求 | 现状 | 备注 |
|---|---|---|
| Web 内通知 | 部分 | approval 已在 chat 页 dock 出现;但需打开 tab 才看到 |
| 桌面通知(OS) | 缺失 | Electron `Notification` / macOS NSUserNotification / Windows toast |
| 邮件通知 | 缺失 | 长时无人确认时降级到邮件 |
| IM 桥接通知 | 待定 | 是否走 L 段的"项目级桥接"自动 push 到 飞书/钉钉/微信/QQ |
| 声音提示 | 缺失 | 桌宠 / TTS(可复用 K 段) |
| 移动端推送 | 缺失 | mobile app push,或 PWA web-push |
| 通知聚合 / 静默策略 | 缺失 | 走 G 段 inbox 聚合;Do Not Disturb 时段;按 session 折叠 |
| 提醒优先级 | 待定 | approval 高优;info 类可降级为静默 |
| 移动端 / 离线场景 | 待定 | 用户不在终端前,提醒能否"找到"用户 |
