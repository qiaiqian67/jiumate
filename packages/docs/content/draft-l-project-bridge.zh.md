## L. 按项目维度:消息桥接 + 模型作用域

观察:本项目已经是多项目架构,但 messaging bridge 和 model 凭证还停留在"项目 / 会话"混用的粒度,缺少"项目作为一级公民"的统一管理。

需求(两条相关但不同):

- **按项目的远程控制**:消息桥接(飞书 / QQ / 微信 / 钉钉等)按**项目**绑定,而非按**对话/会话**绑定;项目下开新对话时自动继承桥接
- **模型区分企业级 vs 项目级**:
  - **企业级**:组织/全局的模型预设,所有项目可见可用
  - **项目级**:项目私有的模型凭证
  - **新项目不重配模型**:创建新项目时,可以从企业预设选 / 从其他项目复用凭证 / 全新配置 —— 不强制重新填 API key

| 需求 | 现状 | 备注 |
|---|---|---|
| 项目级消息桥接 | 缺失(当前在 session 级,见 `messaging_bindings` 表) | 把 binding 提升到 project 粒度;session 级仍可 override |
| 桥接继承 | 缺失 | 项目下 session 自动继承项目的桥接;支持显式覆盖 |
| 企业级模型预设 | 部分支持 | 现有 `PUT /models` 是整表声明式,需要新加"企业级"作用域(组织下所有 project 可见) |
| 项目级模型凭证 | 部分支持(`.project_config.toml` 0600,owner 可写) | 已有 per-project 凭证,需要"复用"流程 |
| 新项目向导:复用模型 | 缺失 | 创建 project 时:① 从企业预设选 ② 从其他 project 复制凭证 ③ 全新配置 —— 默认 ① |
| 模型作用域 UI | 待定 | 模型管理页按"企业 / 项目"分组;凭证仍 masked |
| 多项目下的桥接隔离 | 待定 | 同一飞书 bot 是否能同时绑多个 project?是否需要 project 路由规则? |
