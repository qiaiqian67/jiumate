# 三种方式添加技能，并让技能的开关真的能开关

- **Date:** 2026-10-12
- **Type:** feature
- **Scope:** `core`, `server`, `web`

[English](2026-10-12-skill-add-and-machine-switch.md)

添加技能只有一句话的说明，而开关画在卡片上却不动任何东西。这一轮把两件事都补上。

## 那个开关之前是假的

技能 TAB 上的启用开关存在 **localStorage** 里，没有任何一个字节发到服务端。所以关掉它之后，那个
Agent 仍然从磁盘上读到那个技能，仍然把它注入提示词。插件的开关从上一轮起已经是真的了，技能这个
只是**摆在旁边的一个装饰**。

这次让它是真的：机器级写进 `<root>/skills-state.json`，Agent 级写进该技能的 `.installs.json` 记录，
`listInstalledSkills` 在**任一**关闭时跳过它——与插件同一形状的两层开关。

Agent 级那个标志放在 `.installs.json` 而不是 `skills/<name>/` 里放一个标记文件，是为了让技能目录
只装技能自己带的那些文件：多出来的任何东西都会被下一次「导出为 zip」顺带走，因为导出是照原样读
整个目录的。

不存在／读不出／损坏一律读作开启。危险的是反过来：默认关闭的话，这个改动一上线就会把每台既有机器
上的每个技能都关掉——没人决定过就自己消失的能力，正是开关唯一不能有的失败模式。

## 三条添加路径

终点是同一个东西：`<root>/skills/<name>/`，也就是本机技能库。三种来源的**获取方式**毫无共同之处，
但装完之后它们对下游（挂载、启用、分类、删除）是完全相同的技能；让它们汇到一处，比让下游每个动作
都分辨「这个技能是从哪来的」便宜得多，也更不容易漏掉某个分支。

- **仓库 URL** ——用户会粘的每一种形状都解析到同一个分支归档。仓库本体、带 `.git` 的、
  `/tree/main` 的、深链到某个文件的。而 `/tree/main` 恰恰是**最可能**被粘出来的那个，因为从浏览器
  复制出来的就是它；把它喂给下载器会拿到一个 HTML 页面而不是 zip。
- **压缩包** ——独立路由而不是给 URL 路由加一个 content-type 分支，因为两者传参方式不同，而原始
  请求体没地方放 JSON。
- **本机目录** ——解析 realpath 之后再读。只有服务端能说一个路径是否存在，而不先解析真实路径就拼接，
  一个符号链接就能把读取引到它本该到不了的目录。

**添加不是安装。** 三条路径只把技能放进本机库；挂载到某个 Agent、启用，是另外两个动作。压缩包和
目录这两种来源尤其需要说清——一次点击可能带来十几个技能，如果「添加」同时意味着「所有 Agent 立刻
开始调用」，那是一次点击产生十几处运行时变更。

**目录本身可以就是一个技能**，不必是装技能的容器。指向 `.../my-skill` 是人最自然的做法，而一个只
认「容器」的读者会对用户亲手挑的那个目录回答「这里没有技能」——那读起来像是扫描坏了，而不是理解
偏了。

## 识别技能：两种布局

顶层 `<name>/SKILL.md`（一个技能一个目录），以及 `.agents/skills/`、`.claude/skills/`。只认后者
会漏掉最直白的那种仓库，而猜错的表现是**「添加了 0 个技能」且不报错**——用户会以为自己添加成功了。

名字永远取目录名（除非整个目录本身就是那一个技能，此时 frontmatter 的名字说了算），与其它所有
列举一致：运行时处处按目录名寻址，让 frontmatter 说了算只会得到一个指向不存在路径的名字。

## 扫描：按目录分组

**按目录而不是拍平**，因为「添加的其实是目录」——同一个 Agent 的一组技能是一起被加进来的，让用户
逐个勾选反而是在问他一个他没有问过的问题。拍平之后要么逐个勾，要么被迫一次性导入整台机器上的
所有技能。

空结果的 Agent 也要列出来：扫过了但它没装，与根本没扫，在界面上是两件能分辨的事，否则两者是同一个
空白。**已在库里的技能标出来并默认不勾**——同名覆盖是有后果的（原来那份可能是用户改过的），所以
勾上它就是用户做这个决定的那一刻。

## 升级：回到当初的来源

`.source.json` 记下来源，因为压缩包解开之后原始文件不在机器上，没有第二个地方可查。这两种情况
**如实报告「无从检查」**，而不是谎称「已是最新」——后者会让用户以为这个技能有人维护。

版本号是 `YYYY-MM-DD.N`，按字段比较而不是按字符串：字符串比较会把两个字段判反（`2026-09-02.1`
在文本上低于 `2026-08-04.1`，因为第十个字符上 `0` < `1`），而把降级当成升级会把用户能用的版本覆盖掉。

## 卡片上的控件

**机器级开关画在最左边**，因为它是更宽的那个：关掉它就一次性对所有 Agent 停用，而这正是用户想要
「让这个技能别再出现在我的机器的行为里」时伸手去按的那一个。它旁边是原有的 Agent 级开关——两者是
不同作用域的两个动作，所以并排而不是互相取代。

**升级只在有来源记录时出现。** 压缩包来源**有**按钮（服务端能回答，答案是「无从检查」，那是一个如实的
结果）；手工复制进来的技能没有来源记录、**没有地方**可查，于是连按钮都不给——一个永远道歉的按钮
的提示没人会读第二遍，而它的缺席本身就是解释。

**内置技能与插件带来的技能没有机器级开关**：它们不在本机库里，给它们挂一个开关，写下去的值没有
任何技能读。

添加对话框里顺带可以选分类，添加完成就落在那个分类里——比添加完再去每张卡片上补一遍省事。
