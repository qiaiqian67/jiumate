# 0.4.0 shipped: the Release is out, npm is one token away

- **Date:** 2026-10-27
- **Type:** release
- **Scope:** `ci`, `tooling`, `docs`

[中文版](2026-10-27-release-0.4.0-shipped.zh.md)

The `v0.4.0` Release is on GitHub now: the program bundles for six platforms, the desktop installers for five, both one-line installers, and their checksums are all published, and every `releases/latest/download/<name>` resolves. This entry records what is left on the release path, and why the one thing that is left cannot be done from inside the repository.

## What is there

**The Release assets.** `v0.4.0` carries 34 of them: `jiumate-<target>.tar.gz` (linux-x64, linux-arm64, darwin-x64, darwin-arm64, win32-x64, universal), `jiumate-desktop-*` (dmg and zip for both macOS architectures, the win32-x64 exe, and the Linux AppImage and deb), `install.sh` and `install.ps1`, the `latest*.yml` and blockmap files that electron-updater reads, two `SHA256SUMS` files, and the download manifest.

**The download links.** The `releases/latest/download` layer is what the site uses: the installers carry version-less names, so one static link always serves the newest release. Every asset's name, size and sha256 in the manifest match; the Windows installer downloaded whole hashes to the published value.

**The CI.** All 21 jobs are green. The first time since the repository opened. Eight gates had never passed, and they had to be fixed before a tag could produce anything:

- **Prettier** had never been run: 187 files did not match the format, and one of them — the installer's renderer — had a `div` left unclosed inside a section, so Prettier could not even parse it.
- **typecheck** failed on one line: `writeInspirationCase`'s `meta` declared `updatedAt` as a `string`, while the schema declares `string | null`, and a preset is written with none.
- **oxlint** failed on three files that import the same module twice, which is exactly what the rule was added for.
- **The license gate** failed on the docx editor's font package: its license is `Apache-2.0 AND OFL-1.1 AND LicenseRef-GUST-Font-License`, and the last of those has no SPDX identifier — it is the GUST Font License, whose operative terms are the LaTeX Project Public License 1.3c. All three are permissive, and the obligations of the two font licenses attach to the font file rather than to the work that embeds it.
- **The test gate** failed on the server shards, and that was the expensive one: 108 test files never loaded, because the shards built core's dependency tree and tested server. Server depends on pets, inspirations and skins; core does not, so those three were never built and the suite could not resolve `@jadelau/pets` before it ran a single test. Every shard that tests server now builds server's tree.
- **Playwright's browser** was not installed, so the five login-figure suites failed at `browserType.launch` with "Executable doesn't exist" — a message that reads like a broken test rather than a missing browser.
- **The POSIX launcher** was committed without the executable bit, so the installer test's `[ -x ]` check failed and the POSIX installer suite never ran.
- **The Windows installer suite** inherited the download source from the environment instead of pinning it per case, so every case that did not set the variable itself ran against whatever the installer's default happened to be. That last one was this round's own doing: changing the default download source broke every case that did not pin the mode itself, which is what a test should have caught sooner.

Two more tests depend on POSIX signals. Ctrl-C has to reach a child in a pipeline, and a stop has to be a signal rather than an exit code, or the session cannot tell a stop from a failure. Windows has neither, so those two are skipped there.

**Three tests were measuring the runner instead of the thing they were about.** These turned up once the CI was green enough to run the same jobs repeatedly, and each one fails on a busy machine while the behaviour it names is exactly right:

- The login page's pupils **poke out of the whites they belong to** while a figure blinks. The travel is a share of the pupil's width, and the blink collapses the white's *height* without touching its width, so the room the pupil's centre has vertically shrinks to almost nothing while the distance it is asked to travel does not. Each axis now gets its own room, read from the white as it is drawn at that moment, and the pupil is clamped to it. This one was not a test problem: a user with the cursor near the page could see it.
- The machine transport's test said that two commands on two machines finish in under 380ms. That constant is a measurement of how fast the runner starts processes. It now compares the parallel run against the queued one — the same machine, the same commands, a moment apart — and the difference between them is a whole sleep, which no amount of process-starting overhead swallows.
- The skill archive test builds archives that are deliberately over the limits, and it was already at 5001ms on a development machine — the suite's 5s default was cleared by a hair. It gets 30s for itself now, and the assertions do not change.

**The scope changed.** `@jiumate` is taken on npm by somebody else, so the thirty-one packages moved to `@jadelau`. npm does not let a published name change, so this is not a redirect: it is a rewrite of every place a package name is written — each `package.json`'s `name`, every `import` and type specifier, every `workspace:*` dependency edge, the `pnpm --filter` selectors in CI and in the release workflow, the install scripts' one-line install advice, and the Trusted Publisher checklist. Two things in the source look like the scope and are not, and the rename script is careful about both: `@jiumate-builtin` is the suffix on a plugin id, and `~/.jiumate` is the data root.

**Three things that were never going to arrive are gone rather than faked.** The Alibaba Cloud OSS mirror: the GitHub Release is the only distribution point now, and the default download source moved from `auto` to `github` because `auto` would spend a round trip discovering the mirror is not there. The signing certificates: the installer's signing steps fall back to an unsigned build when the keys are absent, and this release ships unsigned. The domain: the site is served from the repository's GitHub Pages address, so the deploy subpath is `/jiumate/` rather than the domain root, and every link that has to be absolute follows — the canonical URLs, the sitemap, robots.txt, the one-line installer commands, and the app's attribution header. The origin and the subpath are separate values, because a domain is served from the root and Pages from a subpath, and the two change independently.

## What is left: 26 packages on npm

Under `@jadelau` there are 26 packages to publish: 19 plugins plus agenthub, inspirations, pets, skins, core, server and cli. Publishing goes through OIDC trusted publishing — no token, npm trusts the workflow through GitHub Actions' identity.

**None of this touches the release.** The npm packages are a second distribution channel beside the GitHub Release, not part of it: the installer downloads a bundle from `releases/latest/download` and never asks npm for anything, and the desktop app bundles the `@jadelau/*` plugins from the workspace — `workspace:*` is a link to the local build, not a registry tarball. In the release workflow the npm job is independent of the build: it runs in parallel, and its failure leaves the Release standing. Nothing in the CI workflow publishes to npm at all.

**They cannot be published right now, for two reasons, neither of them in the code.**

The first is that **the OIDC token exchange returns 404**. The trusted publisher npm has configured for these packages does not recognise this workflow, so it falls back to an ordinary token, and this machine has none.

The second is that **23 of the packages do not exist on the registry at all**. npm's `PUT` for a package that does not exist returns 404, and a trusted publisher can only be configured for a package that **already exists** — npm's settings page lists the packages a workflow can be pointed at, and a name that was never published is not in that list. So the first version has to go out with a one-off token, which puts the packages on the registry, after which trusted publishing can be configured for them.

Three of them are already on: `@jadelau/core`, `@jadelau/a2ui` and `@jadelau/agenthub`, all at version `0.0.0-stage`, described as *"Temporary package placeholder for staged publishing"*. The other 23 are not.

**How to do it**: `scripts/bootstrap-npm-publish.mjs` exists for this. It publishes all 26 in dependency order (the plugins first, because core depends on them; then agenthub; then core, server, cli), rewrites every `workspace:*` specifier to the version it points at, and publishes each one once. Its `--dry-run` has been run: it recognises all 26 packages and knows which three are already there.

It needs a **granular token with publish rights**, in `NPM_TOKEN` or in `~/.npmrc`. Revoke it once the packages are out.

**Configuring the trusted publisher afterwards does not take twenty-six web forms.** npm's settings page has one form per package, and `npm trust` is the same configuration from the command line — so `scripts/configure-npm-trust.mjs` fills the form in once and runs it for all twenty-six. It is the same shape as the bootstrap script next to it: `--dry-run` shows what it would do, `--only <name>` does one package.

> npm now requires two-factor authentication for publishing: either an account with 2FA enabled plus a token, or an account with 2FA enabled plus a trusted publisher. Both roads reach the same place — the token has to be created by whoever holds the account. Note that the token must **not** have "bypass 2FA" enabled: npm refuses trusted-publisher configuration with such a token, and the account needs 2FA switched on regardless.

## Found along the way

**This release moved the tag three times.** `v0.4.0` started on `dda2e5e`, which predates the scope rename and the green CI. It had never produced a Release, so moving it to the current commit was safe — the guard in release.yml says as much: a tag whose version does not match the repo gets re-tagged.

**Two Pandoc archives root at different directories.** The macOS ones root at `pandoc-3.5-arm64/` and `pandoc-3.5-x86_64/`; the Windows and Linux ones root at `pandoc-3.5/`. The code had all three paths identical, so the macOS desktop build failed on a file that was there under another name. The paths now say what each archive really contains, and there is a fallback: if the declared path is not there, the binary is found by name and the build says which path it took — a Pandoc release renaming its root should not stop a release.

**The Windows desktop build ran its steps in the wrong order.** The installer's `build` is the shipping path: it packs the Windows payload. That payload is electron-builder's to produce, and electron-builder runs after the recursive build — so the installer ran early, against a payload that did not exist yet. It is now excluded from the recursive build on Windows as it is on the other two platforms, and built for real once the unpacked tree is there.

## Compatibility

- **The npm packages are not out yet**: `npm install -g @jadelau/cli` does not work. To install the program, use the installer script from the Release.
- **The installers are unsigned**: macOS and Windows will say the app is from an unidentified developer.
- **There is one download source**: the mirror is gone and `install.sh` downloads from the GitHub Release.
- **The site's address**: `https://qiaiqian67.github.io/jiumate/`.
