# 插件有了本机级开关，每张卡片都有

- **Date:** 2026-10-12
- **Type:** feature
- **Scope:** `core`, `server`, `web`

[English](2026-10-12-plugin-machine-switch.md)

插件的启用开关此前只存在于「装在当前选中 Agent 上」的插件。`use-claude-code` 装在 `cc` 上而没装在 `default_agent` 上，所以带着 `default_agent` 打开这一页时，它根本没有开关——看起来就像它无法被关闭。这次改动补上了缺失的那一层：插件是否**在本机**启用，库里的每一个插件都能回答。

## 为什么需要第二个标志

原有的开关写在 `agent_state/plugins/<id>/manifest.json` 里，所以它回答的是「**这个** Agent 要不要调用它」，而且只能为一个该 Agent 已安装的插件存在。「这个插件该不该存在于这台电脑上」是另一个作用域不同的动作，而且必须能在任何东西被安装到任何地方之前就表达出来——而新插件在你第一次决定要不要它的时候，正处在那个状态。

两者都保留，且**必须都为开**，插件的技能才会加载。把本机开关关掉，会一次性对所有 Agent 停用该插件，而不去改动任何一份清单，因此 Agent 级的状态得以保留，等本机开关重新打开时一并恢复。两个标志都不会覆盖对方。

## 状态存放

- **`<root>/plugin-state.json`**，一个由库名构成的 `{ disabled: [...] }` 列表。别的什么都不记录：处于开启状态的插件就是不在列表里，所以这个文件只承载例外情况，而「不在」也持续意味着「开启」。
- **按库名而非插件 id 作键。** id 带有 `@marketplace` 后缀，而同一个名字在一台机器上可能解析到两份副本中的任意一份；一个只要解析结果不同就得换键的开关，会自己从用户的设置底下挪走。
- **文件不存在、读不出、损坏，一律读作已启用。** 反过来默认的话，这个文件一出现就会把每台既有机器上的每个插件都关掉——一种没人决定过就自己消失的能力，正是开关唯一不能有的失败模式。这也是 Agent 级清单早就使用的同一条规则。
- **原子写入**，因为这个文件就是「这个插件开着吗」的全部答案，而写到一半的文件会被读作损坏、进而读作已启用。

## 它约束了什么

- **安装。** `POST …/agents/:a/plugins` 回答 **409 `plugin_disabled`** 并点名被关掉的插件。整批拒绝而不是过滤掉那几个，这样一个点了两个插件的请求永远不会半成功，让调用方猜不出哪一个落地了。检查放在路由而不是 `installPlugin` 内部，因为 core 同时是 SDK 也服务 CLI——这条规则属于本产品的两级开关，而直接写安装树的调用方并不经过这条守卫所保护的界面。
- **运行。** `listInstalledSkills` 在*任一*标志关闭时跳过该插件，因此已经装在某个 Agent 上的插件会在本机开关拨动的瞬间停止进入它的提示词。机器级的集合每次列举只读一次，而不是每个插件目录读一次。
- **进行中的会话。** `POST /api/plugins/enabled` 作废**每个 Project 中每一个已缓存的运行时**，而不只是某一个 Agent 的。技能是在每次构建会话时从磁盘读取的，但进行中的会话早已组装好了提示词——而这个开关没有 Project 可以用来限定影响范围，于是让其他 Project 保持缓存就意味着同一个插件对某个 Agent 开启、对另一个关闭，直到各自恰好被逐出。`SessionManager.invalidateAllRuntimes` 是新增的；既有的按 Project 变体无法表达这件事。

## 卡片

- **本机开关出现在每一张插件卡片上**，不加任何条件。它此前以「装在选中的 Agent 上」为条件，而这正是让装在别处的插件看起来根本没有开关的原因。还没有任何 Agent 安装的插件同样有开关——那恰恰是做决定时的状态。
- **两个开关并排出现**，而不是一个取代另一个。它们是两个作用域不同的动作，把它们合并，要么会丢掉全机的总开关，要么会丢掉 Agent 级的那个。
- **在本机关闭期间，某个 Agent 的「安装」按钮被禁用**，并带一个说明如何解除的提示。禁用而非隐藏：想要这个插件却找不到按钮的用户，无法区分「是我故意关的」和「这个应用装不了」。
- **已装有该插件的 Agent 上，「卸载」仍然可用。** 本机关闭阻止的是安装与运行；它不阻止文件被删除。
- `PluginItem.enabled` 是**必填而非可选**。卡片对每个插件都显示开关，不论有没有 Agent 装过它，所以这个列表无法用「省略字段」来回答「未知」。

## 兼容性

不重写任何既有数据，也没有东西被破坏。新文件在有插件被关闭之前并不存在，在那之前每个插件都读作已启用——而它们本来全都是启用的。用户早先设过的某个 Agent 级 `enabled: false` 依然完全照旧生效；机器级标志只是不存在，对判断不增加任何东西。

唯一可见的差别：一个此前被某个 Agent 关闭、而当前**选中的是另一个** Agent 的插件，现在会显示一个过去根本不渲染的本机开关。这正是修复本身，而非含义的变化。
