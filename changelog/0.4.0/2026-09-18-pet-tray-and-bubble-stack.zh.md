# 给桌面宠物补上系统托盘入口、角色列表刷新与可滚动气泡栈

- **Date:** 2026-09-18
- **Type:** feature
- **Scope:** `desktop`, `web`

[English](2026-09-18-pet-tray-and-bubble-stack.md)

参考实现有、而这份移植还没有的三项能力：从通知区域控制宠物、按需重新读取宠物目录、以及不再静默丢弃较旧会话的气泡栈。

## 托盘

- 宠物启用期间，应用会在通知区域保留一个图标，包含可勾选的「显示桌面宠物」，以及「显示主窗口」「退出」。对齐 OpenBitFun 的 `tray.rs` 入口。
- 该图标**只在宠物启用时存在**。关闭主窗口本来就会退出应用（除非宠物窗口还开着），而一个比宠物活得更久的托盘会悄悄把应用变成用户从未要求的后台进程。
- `enablePet` 偏好住在渲染进程里，所以这个菜单项是转发而不是直接写入：点击会请求聊天窗口翻转偏好，聊天窗口再通过 `pet:setEnabled` 把状态回报给外壳——外壳拿不到 `ui_prefs`。
- 文案跟随操作系统语言（主进程没有界面词典），图标用 128px 的渲染结果复制为 `dist/tray.png`，而不是 1024px 的主图（通知区域按约 16px 绘制）。

## 设置

- 新增「刷新列表」，按需重新读取宠物目录。导入或删除后本来就会刷新，但手工丢进数据目录的包（或由共享该目录的另一台主机放入的包）此前只能靠重开对话框才能看到。

## 气泡

- 现在每个被跟踪的任务都会得到一个气泡。气泡栈会在超过外壳 240px 上限时滚动，而不是静默丢弃最旧的会话；聊天侧本就把列表限制在 `PET_MAX_TRACKED_TASKS`。
- 气泡栈的高度由页面以内联方式给出，而不是在 CSS 里写百分比：百分比会对着 dock 的 auto 高度解析，导致气泡栈溢出窗口且被裁掉，而不是在窗口内滚动。
- 气泡栈改用 `margin-top: auto` 锚底，而不是 `justify-content: flex-end`。配合 `overflow-y: auto` 时，flex-end 会把溢出推到块起始方向、落在可滚动区域之外，于是被裁掉且无法到达。

## 兼容性

- 没有新增偏好，也没有数据迁移；托盘用的是渲染进程本来就有的状态。
