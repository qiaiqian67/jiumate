# 主题：一个主题 = 一套配色 + 一张画

- **Date:** 2026-09-19
- **Type:** feature
- **Scope:** `@prismshadow/jiumate-skins`（新工作区包）、`packages/server`、`packages/web`、`packages/desktop`

## 背景

设置页原本有三个并列的东西：「主题」（其实是明暗外观）、「皮肤」（配色）、「壁纸」（图片）。这三者被当成互不相干的层，于是每加一张图就要为它发明一套配色，而"主题"这个词指的是明暗开关——**真正是主题的东西反而叫皮肤**。

本条目把它们收敛成一个概念，格式与模型对齐 [Codex Dream Skin](https://github.com/Fei-Away/Codex-Dream-Skin)：**一个主题就是一套配色加一张画**，外加构图。

## `@prismshadow/jiumate-skins` — 新工作区包

主题的 IO、校验与渲染。格式是 Dream-Skin 的，**采纳而非翻译**：同一个 `theme.json`（十个颜色角色 + `art` + `appearance` + 一张 `background.*`）两边都能读，所以那个项目的主题——包括社区主题库——不需要转换就能导入。

- **`colors`** — 十个角色，声明时必须齐全：`background` / `panel` / `panelAlt` / `accent` / `accentAlt` / `secondary` / `highlight` / `text` / `muted` / `line`。
- **`appearance`** — `light` / `dark` / `auto`，描述的是**外壳**，不是配色。单模主题会把明暗设置钉死（本应用不绘制的那部分窗口——原生滚动条、表单控件、`color-scheme`——必须与画作一致）；`auto` 跟随用户的设置。
- **`art`** — `focusX` / `focusY` / `zoom` / `dim` / `safeArea`（`left` / `right` / `none`）/ `taskMode`（`ambient` / `full` / `off`）。
- **色阶是推导的，不是声明的。** 界面组件读的是 Tailwind 色阶，而**同一个名字在两种模式下角色相反**——`gray-50` 在浅色下是页面、在深色下是正文。所以一套绝对色要铺两遍：`--color-gray-50` 和 `--color-gray-950` 都取 `background`。作者只写一套颜色。
- **`--color-white` 是唯一一个角色会变的 token。** 浅色外壳下它是主表面（`bg-white`，67 处调用点里 63 处带 `dark:` 兜底）；深色外壳下兜底接管了那件事，剩下的是"深底上的墨色"（`bg-gray-700 text-white`、`bg-black/50` 遮罩上的说明文字）。深色读法里指向 `panel` 会把这些变成深字配深底。
- **表面透明度是用户偏好，不是烘进颜色里的常数。** 主题声明哪些 token 是表面，宿主在渲染时对它们施加用户选的 alpha。

## `packages/server`

- **`/api/skins`** — `GET` 列出已安装主题 + 诊断；`GET /api/skins/:slug/asset/:name` 只下发清单声明过的资源；`POST /api/skins/import` 接受 `{ path, expectedFingerprint? }`，先校验后发布；`DELETE /api/skins/:slug`。
- **`PUT /api/me/prefs`** — `activeSkinLight` / `activeSkinDark` / `activeWallpaper` 三个键合并为 **`activeTheme`**。一个选择而不是两个：主题自带配色和画作，由 `appearance` 决定是否钉住外壳。

## `packages/web`

- **设置页改为一个主题画廊。** 卡片显示主题自己的画作（没有画作就显示从调色板生成的色卡），角标说明它是固定明暗还是跟随。选中即生效。
- **`jiumate.theme` 现在是主题选择**；明暗设置搬到 `jiumate.mode`。此前两者共用 `jiumate.theme`，会互相覆盖。表面透明度与画作压暗移到 `jiumate.theme.*`。
- **内置画廊 9 个主题。** `gothic-void-crusade` 是 Dream-Skin 的真实画作（MIT，见 `THIRD-PARTY-NOTICES.md`），带作者声明的调色板；其余八张画作是本仓库手写的 SVG，配色取自画面本身。都遵循那个项目记录的构图契约：左侧约 52% 保持低信息、低对比，主体集中在右侧。

## `packages/desktop`

- **主题导入的原生文件夹选择器**（`theme:pickFolder` → `window.theme`）。独立于 `pet:pickPackage`，因为后者的对话框标题和桥接命名都是给宠物用的。对话框标题按 `app.getLocale()` 取中英文，与托盘菜单同一套做法。
- 选择器只是**加速器**：纯浏览器里没有它，所以路径输入框仍是主控件，两者共用同一次导入。

## 未包含

- **`theme.css`（Safe CSS）只报告、不应用。** Dream-Skin 的导入器对新包强制要求它，所以从社区主题库拿到的主题一定带着它。本应用会应用配色和画作，但**忽略那张样式表**——也就是缺了作者写的圆角、毛玻璃、阴影和字体。现在导入时会点名说明并讲清代价，不再默默丢掉；Dream-Skin 主题里的文案本来就是这么警告的，所以对一张会改变主题**观感**的样式表保持沉默，是我们自己行为不一致。真正支持它是代码执行面，需要选择器、属性、变量三层白名单，单独一轮做。
- **图片自动分析。** 那个项目会从画作推导主色调与 `art` 元数据；本仓库的内置画作构图是手写时设计好的，不需要推断。真正需要它的是"用户拿自己的图新建主题"那条路。
