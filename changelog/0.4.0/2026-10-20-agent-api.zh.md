# 让 Web App 之外的程序调用智能体

- **Date:** 2026-10-20
- **Type:** feature
- **Scope:** `server`, `web`, `docs`

[English](2026-10-20-agent-api.md)

智能体现在可以对外暴露给 Web App 之外的程序。owner 打开该智能体的 API 标签页，打开开关、创建一把密钥，程序带上这把密钥就能通过 HTTP 调用这个智能体。标签页负责暴露设置和密钥列表；调用侧是 `/amsp/v1` 下的四个路由。

## 标签页

- 启用 Agent API、允许免密钥访问、审批模式、思考强度、工作区、并发上限 —— 每一项都是从服务端读回来的，而不是照着自己发出去的值显示。`open` 尤其如此：`enabled` 为 0 时它被强制为 0，所以一个显示"我刚才请求了什么"的标签页，会显示服务端并不持有的设置。
- 密钥只在创建时显示一次，在一个明说不会再显示第二次的对话框里。服务端只保留它的 sha256，之后无法再复现那个密钥；列表里显示的是前缀、创建时间和最后使用时间。
- 删除密钥从下一个带上它的请求起生效。

## 调用侧

- `POST /amsp/v1/projects/:p/agents/:a/sessions` 在一个请求里创建会话并发出第一轮，回应 `202` 和会话 id。一轮运行要等模型，所以运行留在服务端继续，答案用 `GET` 读，或者用 SSE 跟着走（`GET .../sessions/:id/stream`）——和 Web App 自己用的切分方式一样。
- `GET /amsp/v1/projects/:p/agents/:a/sessions/:id` 回应会话的状态和消息。
- `DELETE /amsp/v1/projects/:p/agents/:a/sessions/:id` 取消正在进行的运行。

## 调用方不能自己挑的东西

模型和审批模式取自智能体自己的设置，不从请求体里读。一个能自己挑模型的调用方，就能让智能体跑在比 owner 授权更便宜的模型上；一个能自己挑审批模式的调用方，就能让对话在更宽松的策略下开始。调用方可以收窄工作区，也可以设思考强度。

## 各种拒绝

- 对不上任何一把密钥是 `401`。
- 没有对外暴露的智能体，和不存在的智能体，是同一个 `404`。这两种情况若给不同的状态码，这个端点就成了枚举服务器上有什么的探测器。
- 为一个智能体建的密钥，指向另一个智能体时也是那个 `404`，而不是告诉它"这把密钥是真的，只是指向别处"。
- 管理员的服务端总开关是 `503`，不是 `404`：所有已暴露的智能体都不可达，而 `404` 会把调用方引去检查一个完全没问题的智能体名。
- 所有槽位都被占满是 `429`，带 `Retry-After`。

## 并发

上限按智能体算，不按密钥算，而且每次取槽位时才读取，所以调低它对下一次运行就生效。槽位在运行期间一直占着，而不是在请求期间：只卡住"发起那一刻"的上限，等于放任并发运行数无上限，而那正是这个上限存在的理由。

## 行跟着什么走

设置行和密钥行跟着拥有它们的 Project 一起被删掉，密钥行跟着创建它们的人一起被删掉。一把比它的智能体活得久的密钥，是一把指向不存在之物的活凭据；而一把比它的主人活得久的密钥，会用外键把那个账户扣住。

## 挂在哪里

调用侧挂在运行时上，在平台接缝之上，和其它运行时自有的面在一起。它是机制面——它认证的是密钥而不是会话——而业务路由由平台 bundle 提供，在一个跑着的安装里，那是最后一次 push 的那个 bundle。两个 loopback 名字都提供它：预览主机的存在是为了让智能体写的预览 HTML 花不掉用户在 Web App 自己的 API 上的会话，而这个面不是 cookie 认证的。

## 兼容性

- 新增两张表。它们不读取也不改写任何已有数据。
- 智能体的 `tools.builtin` 列表没有变化，也没有任何智能体因此多出一个工具：这个面是给程序通过 HTTP 用的，不是给智能体自己用的。
