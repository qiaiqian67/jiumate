# Themes: a theme is a palette and a picture

- **Date:** 2026-09-19
- **Type:** feature
- **Scope:** `@prismshadow/linsight-skins` (new workspace package), `packages/server`, `packages/web`, `packages/desktop`

## Why

The Appearance page offered three parallel things: "Theme" (which was really the light/dark look), "Skin" (the palette) and "Wallpaper" (the picture). Treating them as unrelated layers meant every new picture needed a palette invented to carry it, and the word "theme" named the light/dark switch — so the thing that actually *was* a theme went by another name.

This collapses them into one concept, with the format and the model aligned to [Codex Dream Skin](https://github.com/Fei-Away/Codex-Dream-Skin): **a theme is a palette and a picture**, plus how to frame it.

## `@prismshadow/linsight-skins` — new workspace package

Theme IO, validation and rendering. The format is Dream Skin's, **adopted rather than translated**: one `theme.json` (ten colour roles, an `art` block, `appearance`, and one `background.*`) reads in both projects, so themes from that project — including its community library — import without a converter.

- **`colors`** — ten roles, all required when the block is present: `background`, `panel`, `panelAlt`, `accent`, `accentAlt`, `secondary`, `highlight`, `text`, `muted`, `line`.
- **`appearance`** — `light`, `dark` or `auto`, and it describes the **shell**, not the palette. A single-shell theme pins the light/dark setting (the parts of the window this host does not paint — native scrollbars, form controls, `color-scheme` — have to agree with the artwork); `auto` follows the user's setting.
- **`art`** — `focusX`, `focusY`, `zoom`, `dim`, `safeArea` (`left` / `right` / `none`) and `taskMode` (`ambient` / `full` / `off`).
- **The ramp is derived, not declared.** Components read Tailwind's ramp, and **that ramp means the opposite thing in the two modes** — `gray-50` is the page under a light shell and body text under a dark one. So one set of absolute colours is laid out twice: `--color-gray-50` and `--color-gray-950` both take `background`. An author writes one palette.
- **`--color-white` is the one role whose job changes.** Under a light shell it is the primary surface (`bg-white`; 63 of its 67 call sites carry a `dark:` fallback). Under a dark shell that fallback does that job, and what is left is ink on a dark chip (`bg-gray-700 text-white`, a caption on a `bg-black/50` scrim). Pointing it at `panel` there paints dark text onto a dark chip.
- **Surface transparency is a user preference, not a constant baked into a colour.** The theme says which tokens are surfaces; the host applies the user's chosen alpha to exactly those when it renders.

## `packages/server`

- **`/api/skins`** — `GET` lists installed themes plus diagnostics; `GET /api/skins/:slug/asset/:name` serves only assets the manifest declares; `POST /api/skins/import` takes `{ path, expectedFingerprint? }` and validates before publishing; `POST /api/skins/import/archive` takes a `.zip` as a raw body; `DELETE /api/skins/:slug` removes an install.
- **`PUT /api/me/prefs`** — `activeSkinLight`, `activeSkinDark` and `activeWallpaper` collapse into **`activeTheme`**. One selection rather than two: a theme carries its palette *and* its artwork, and `appearance` is what decides whether it pins the shell.

### The ZIP reader is hand-written, and that is the point

`packages/skins/src/zip.ts` parses the two methods a theme archive actually uses (`stored` and `deflate`), so the hard part is Node's `zlib` and the parsing is ~400 lines rather than a dependency. What a library would *not* buy is the part that matters: **an archive is untrusted input, and every check is a decision about what an attacker gets to name.** Those are clearer stated than delegated.

A ZIP is a naming attack surface before it is a compression format, so the reader refuses:

- **Traversal** — `..`, a leading `/`, a backslash, a drive letter, a NUL.
- **Nesting** — entries must be one flat filename, optionally under a single shared top-level directory (what `zip -r my-theme/` produces). Deeper paths are refused rather than flattened, because flattening two `assets/background.jpg`-style entries would silently collide.
- **Symlinks and other non-regular entries** — refused via the external-attributes mode bits. Writing a symlink from an archive is how a later write escapes the root.
- **Encryption** (flag bit 0), **any method but `stored`/`deflate`** (refused by name, so an exotic method cannot fall through a default branch), and **ZIP64** (a sentinel `0xffffffff` size would otherwise be read as a literal 4 GiB).

Declared header sizes are attacker-controlled, so they are used for *refusal* and **never for allocation**: decompression is capped by `zlib`'s `maxOutputLength`, and the result is then checked against the declared value — a header that lies about being small still cannot produce a large buffer. There is deliberately **no compression-ratio check**; `maxOutputLength` stops a bomb at the same byte on the *real* output rather than a header's claim, and a ratio ceiling would reject honest input, since a repetitive file legitimately compresses far better than a photograph does.

Limits: 32 MiB archive, 12 MiB per entry, 64 entries. An uploaded archive is extracted to the OS temp directory and then handed to the **same** `loadSource` → `publish` path a folder import takes, so an uploaded theme is held to exactly the rules a folder is — including the per-asset size check that `stat`s *before* reading. Idempotency is keyed on the archive's own SHA-256 rather than a path, since a re-upload has no stable path.

## `packages/web`

- **The Appearance page is a theme gallery.** A card shows the theme's own artwork, or a swatch built from its declared palette when it has none, and a badge says whether it pins the light/dark setting or follows it. Selecting one applies it.
- **Three ways in, one import.** A native folder dialog (desktop only), a typed path, and a `.zip` upload — the last being the only one that works in a plain browser and the only one that accepts a theme downloaded from elsewhere. All three share one `runImport`, and all three select what arrived: an import whose effect the user cannot see reads as a failure.
- **`linsight.theme` now holds the theme selection**; the light/dark setting moved to `linsight.mode`. The two previously shared `linsight.theme` and overwrote each other. Surface transparency and artwork dimming moved to `linsight.theme.*`.
- **The word "theme" now means the theme.** The row above the gallery is 「明暗」/“Appearance” (`mode`, `modeInfo`); the gallery is 「主题」/“Theme” (`themeTitle`, `themeInfo`). Previously the light/dark switch was labelled “Theme” and the real theme was labelled “Skin”/“皮肤”.
- **Nine built-in themes.** `gothic-void-crusade` is real artwork redistributed from Dream Skin under its MIT licence (see `THIRD-PARTY-NOTICES.md`) with the palette its author declared; the other eight are SVG written in this repository, with palettes taken from the artwork's own colours. All follow the composition contract that project documents: the left ~52% stays calm and low-contrast, and the interest concentrates to the right.
- `public/wallpapers/` is now `public/themes/`, since a theme's artwork is not a separate layer.

## `packages/desktop`

- **A native folder picker for theme import** (`theme:pickFolder` → `window.theme`). Separate from `pet:pickPackage`, whose dialog title and bridge namespace are both named for pets — reusing either would put the wrong words in a system dialog. The dialog title comes from `app.getLocale()`, the same way the tray menu resolves its labels.
- The picker is an **accelerator**: it does not exist in a plain browser, so the path field stays the primary control and all routes share one import.

## Not included

- **`theme.css` (Safe CSS) is not applied — only reported.** Dream Skin's importer requires it for any new package, so a theme from that community library arrives carrying it. This host applies the palette and the artwork and **ignores the stylesheet**, which means the theme is missing the radius, blur, shadow and typography its author wrote. The import now says so by name and says what it costs, rather than dropping the file in silence; the copy strings in a Dream-Skin theme already warned this way, so staying quiet about a stylesheet that changes how the theme *looks* was an inconsistency. Supporting it is a code-execution surface needing selector, property and variable allowlists, and is its own change.
- **Image analysis.** That project derives an accent and `art` metadata from the picture. The built-in artwork here was composed by hand with its framing designed in, so nothing needs inferring; the route that would need it is "make a theme from your own image".
