# 技能卡片与插件卡片用同一套按钮，并补上缺失的挂载接口

- **Date:** 2026-10-12
- **Type:** fix, feature
- **Scope:** `core`, `server`, `web`

[English](2026-10-12-skill-card-parity.md)

技能卡片上的控件与插件卡片是**两套**。这一轮把它们统一。

## 下拉框去掉了

原来的技能卡片角落是「插件捆绑」+ 分类下拉 + 开关。两个问题，都不是样式问题：

**它们都不是动作。** 「插件捆绑」是一个徽章，它陈述事实；而把技能放进某个分类，是上方那排分类芯片和「管理分类」负责的事——这个页面本来就有一个专门的分类管理体系，卡片上再挂一个下拉，是同一件事的第二个入口。

**在一排图标按钮里放两个带文字的控件，那一行就自成一个系统。** 插件卡片上是五个 28px 的无边框图标加一个开关；技能卡片上有两个带文字的下拉。眼睛读到的是两个页面，而不是一个页面的两个视图。

现在技能卡片是同样的五个控件、同样的图标、同样的顺序：**升级 / 快捷调用 / 管理安装 / 启用禁用 / 删除**。

来源和分类移到了 meta 行（版本号已经在那里）——它们是关于这个技能的信息，不是控件。

## 快捷调用、管理安装、删除真的能用了

这三个按钮之前**点了没反应**——我上一轮只画了机器开关和升级，把它们列进了需求但没实现。这次补齐：

**快捷调用**走页面已有的草稿机制，只有当前 Agent 确实装着这个技能时才可用——和插件卡片同一个规则。

**管理安装**需要一个新的后端接口：`POST /skills/:name`，把本机技能库里的技能挂载到某个 Agent。这条路径之前**不存在**，只有卸载有。

挂载与卸载是**两个 Agent 作用域的动作**，和删除（本机）是两回事：卸载只去掉那个 Agent 的目录，本机那份留着，所以重新挂载只要点一下，技能不会丢。把三件事混成一件事，是用户丢掉本来想留到下次用的技能的方式。

**删除**去掉本机技能库里的那份，Agent 的副本不动。

## 图标收在一处

四个图标路径原先散在两个文件里（`plugins-page.tsx` 和 `session-row-menu.tsx`），现在在 `card-icons.ts` 里共用。**能复用的就复用**——垃圾桶仍然用 `session-row-menu.tsx` 里那一个：为了「同款」而重新描一条看起来差不多的路径，恰恰是这个模块要消灭的那类分歧，在并排的图标行里是能看出来的。

## 顺带修掉一个真 bug

`readMachineSkillFiles` 的 `walk` **只处理当前层，从不进入子目录**——所以技能在 `reference/API.md` 这类子目录里的辅助文件从来读不到。

也就是说：**任何带子目录文件的技能，装到 Agent 上时都会丢掉那些文件**，装出一个引用不到自己文档的技能。

这个 bug 从三个提交之前就在了，一直没有测试覆盖到——我上一轮写的「本机库里能看到载荷文件」那个测试断言的是 `replaceSkillDirectory` 写进去的那一层，而不是读出来的那一层。读和写两条路径都存在，而只有写的那条被测了。

递归是三个提交之前就该有的。
