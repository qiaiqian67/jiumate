# 0.4.0 发布：CI 变绿，scope 换名，不再依赖域名、OSS 与签名

- **Date:** 2026-10-27
- **Type:** release
- **Scope:** `ci`, `tooling`, `docs`

[English](2026-10-27-release-0.4.0.md)

0.4.0 终于能发布了。这一条记录三件事：包名从 `@jiumate` 换到 `@jadelau`；发布链上三样拿不到的东西（域名、阿里云 OSS 镜像、代码签名证书）被去掉而不是被假装；以及 CI 从仓库开张起就没绿过一次这件事——修它比修别的东西都费劲。

## scope 换名

`@jiumate` 这个 scope 在 npm 上被别人占了，所以 31 个包改到 `@jadelau` 下。npm 不允许改已发布包的名字，所以这不是重定向，而是把**每一个写了包名的地方**都改一遍：每个 `package.json` 的 `name`、每一处 `import` 与 type specifier、每一条 `workspace:*` 依赖边、CI 与发布工作流里的 `pnpm --filter` 选择器、安装脚本里的一行安装建议，以及 Trusted Publisher 清单。

有两处**看起来**像 scope、其实不是的，改名脚本对它们很小心。`@jiumate-builtin` 是插件 id 的后缀，插件库是按它寻址的，所以它原样保留。`~/.jiumate` 是数据目录，`jiumate/` 是仓库名，两个都不是包名。

改名脚本本身留在了 `scripts/rename-npm-scope.mjs`：这个项目下一次需要换 scope 时，还是同样一套文件、同样一遍走，用手工做就是一个名字会在某个地方被漏掉。

## 三样拿不到的东西

**阿里云 OSS 镜像没有了。** GitHub Release 现在是唯一的分发点：安装包和下载清单都上传到它，`install.sh` 从它下载。镜像的代码还留在脚本里——哪一天有了镜像，设 `JIUMATE_DOWNLOAD_SOURCE=auto` 就重新用上，GitHub 一直是它的兜底。默认值从 `auto` 改成 `github`，因为 `auto` 会先花一个来回去发现镜像不在。

**安装包没有签名。** 签名需要 Apple Developer ID 和 Windows EVSign 账户，这次两样都没有；桌面工作流里签名那两步在没有密钥时会自动降级成未签名构建，于是两个开关都拨成 false，产物以未验证的状态发布。

**域名没有了。** 站点现在伺服在仓库的 GitHub Pages 地址上，所以部署子路径是 `/jiumate/` 而不是域名根，每一个必须绝对的链接都跟着走：canonical URL、sitemap、robots.txt、一行安装命令，以及 App 自己的对外标识。域名和子路径是分开两个值，因为域名伺服在根、Pages 伺服在子路径，两者独立变化，绑在一起就会写出一个重重的路径。站点的 `install.sh` 与 `install.ps1` 是从 GitHub Releases 下载的薄转发器，所以安装命令从来不需要域名能解析——只需要一个稳定的地址可以粘贴。

`APP_URL`（harness 打在 OAuth key 上的对外标识）指向仓库而不是一个宣传域名：它是一个标识，必须在每个版本之间保持不变，而它应当指向软件所在的地方。

## CI 从来没绿过

这个仓库的每一个 workflow 运行都是失败的，从 2026-09-17 起每个 job 在 1 到 9 秒里就死了，账户额度那条消息盖住了真正的原因。额度修好之后，门禁自己露了出来，一共八个：

- **Prettier** 从没被跑过：187 个文件不符合格式，其中一个 `packages/installer` 的渲染器还缺一个闭合的 `div`，Prettier 连解析都做不到。
- **typecheck** 挂在一行上：`writeInspirationCase` 的 `meta` 把 `updatedAt` 声明成 `string`，而 schema 声明的是 `string | null`，而一个 preset 就是以 null 写的。
- **oxlint** 挂在三个把同一个模块 import 两次的文件上——这条规则就是为这件事加的。
- **license** 挂在文档编辑器的字体包上：它的许可证是 `Apache-2.0 AND OFL-1.1 AND LicenseRef-GUST-Font-License`，最后一个没有 SPDX 标识符，它是 GUST Font License，其实际条款是 LaTeX Project Public License 1.3c。三个都是宽松的，而两个字体许可证的义务落在字体文件上，不落在嵌入它的作品上。
- **测试** 挂在 server 分片上，而且是最费劲的一个：108 个测试文件根本没加载，因为分片建的是 core 的依赖树而测的是 server。server 依赖 pets、inspirations 与 skins，core 不依赖，于是这三个从没被构建，套件在跑第一个测试之前就解析不了 `@jadelau/pets`。现在每个测 server 的分片都建 server 的那棵树。
- **Playwright 的浏览器** 没装，五个登录页小人的套件在 `browserType.launch` 处报 "Executable doesn't exist"——这句话读起来像测试坏了，而不是浏览器没装。
- **POSIX launcher** 没有可执行位，所以安装器测试的 `[ -x ]` 检查失败，POSIX 安装器套件从来没跑过。
- **Windows 安装器测试** 从环境里继承下载源而没有按用例固定，于是每个没有自己设变量的用例都在跑安装器当时恰好有的默认值上。

**最后一条是我自己造成的**，值得写下来：把默认下载源从 `auto` 改成 `github`（因为镜像没有了）之后，测试报"canonical 发了 2 个请求，预期 3 个"。它发的正是该发的两个：那些用例测的是安装器**选哪个源**，而默认源不是它们要测的东西。现在每个用例自己写明它测哪个模式，就像 POSIX 那个套件本来就在做的那样。

另外，**Windows 上有两个测试依赖 POSIX 信号**：Ctrl-C 要能到达管道里的子进程，一次停止要是一个信号而不是一个退出码，否则会话分不清"停止"和"失败"。Windows 两样都没有，所以那两个在 Windows 上跳过——这个仓库里另外二十来处 Windows 守卫是同一个做法。

## 域名换掉之后要重新看的地方

站点的部署子路径从 `/` 变成 `/jiumate/`，所以资源路径、canonical URL、sitemap 和 Open Graph 图片全都跟着变。域名与子路径被拆成两个独立的值（`SITE_ORIGIN` 与 `BASE_PATH`），因为它们独立变化。

## 兼容性

- **npm 上的包名变了**：`npm install @jiumate/core` 不再解析，`@jadelau/core` 开始解析。旧名字从未发布过，所以没有东西需要 unpublish，也没有版本需要 deprecate。
- **仓库里的导入路径**随包名一起变了，仓库外没有源码受影响。
- **安装包未签名**：macOS 与 Windows 会在首次运行时说应用来自未知开发者。
- **安装源只有 GitHub**：镜像没有了，`install.sh` 直接从 GitHub Release 下载。
- **站点地址变了**：`https://qiaiqian67.github.io/jiumate/`。
