# 0.4.0 已准备好发布，但四个外部条件还没到位

- **Date:** 2026-10-23
- **Type:** process
- **Scope:** `ci`, `tooling`

[中文版](2026-10-23-release-0.4.0-blocked.zh.md)

0.4.0 的代码、changelog 与版本号都已就绪，tag `v0.4.0` 已推送，但发布没有完成：GitHub 上没有 Release，npm 上没有包，OSS 镜像上是空的。本条目记录发布被什么挡住，以及这些挡路的东西不在仓库里、因而无法由一次提交修好。

## 仓库这边已经就绪的部分

- `changelog/0.4.0/` 收着这一轮的全部 32 条条目（中英成对），`RELEASE.md` 是 GitHub Release 的正文。
- 根与 `packages/*`、`plugins/*` 的 `version`，以及 core 的 `VERSION` 常量，都是 0.4.0——发布工作流会拒绝一个版本对不上的 tag。
- `v0.4.0` 打在 `021ff2e` 上，`RELEASE.md` 在那个 commit 里，所以工作流能读到它。
- typecheck 过了五个包，core/server/web/cli/desktop 的套件在本地跑通，构建产物能出来。

## 挡在发布前面的四件事

**GitHub Actions 的账户额度。** 从 2026-09-17 起，这个仓库的每一个 workflow 都以同一条消息失败：*"The job was not started because recent account payments have failed or your spending limit needs to be increased."* 每个 job 在 1 到 9 秒里就死了，因为它们根本没有启动。2026-09-17 之前的 run 里还有 12 个成功的（`Deploy Site` 与 `CI`），之后一个都没有。这是账户设置里的事，不在代码里。

**npm 的 Trusted Publisher 没配对。** 0.3.0 那次发布（`34331535137`）走到了 `Publish to npm` 才失败：OIDC 的 token 交换返回 404，于是 pnpm 退回用一次性 token 去 `PUT /@linsight%2fagent-development`，registry 回 404。原因是那个包在 registry 上还不存在——Trusted Publisher 只能为一个**已经存在**的包配置。`@prismshadow/jiumate-cli` 及它的依赖链今天都还不在 npm 上。

**Windows 签名密钥没配。** 同一个 run 里，桌面安装包的构建写着 *"Missing EVSIGN_KEY secret required for Windows release signing."* 仓库的 `THIRD-PARTY-NOTICES.md` 记着签名身份是 `NaisNet Technology Co., Ltd.`，但密钥本身是仓库的 secret，不在仓库里。

**OSS 镜像的 environment 没配。** `mirror-oss` 作业抱怨 `ALIYUN_OIDC_PROVIDER_ARN is not configured in the oss-production environment`。

## 顺带发现的事

**0.3.0 从来没有真正发布出去。** 它的 Release run 里 `check-release` 过了，`Publish npm packages` 失败，`release`、`desktop` 与 `Mirror GitHub Release to Alibaba Cloud OSS` 三个作业一个都没跑。GitHub 上至今没有 `v0.3.0` 这个 Release，`release list` 是空的。

**现在没人能通过官方渠道装到这个软件。** 仓库里的安装器指向 `https://jiumate.ooo/install.sh` 与 `https://jiumate-releases.oss-cn-beijing.aliyuncs.com`，但 `jiumate.ooo` 的 DNS 解析不到，OSS 那个 bucket 上 `/`、`/releases/` 与 `/latest.json` 全是 404。`penguin.ooo` 还能访问，但它伺服的是改名前的旧安装器，指向另一个 GitHub 仓库。

**tag 已经推上去了。** 账户额度修好之后，重跑同一个 tag 就行——发布链上的每一步都是幂等的，已经存在的版本会被跳过。
