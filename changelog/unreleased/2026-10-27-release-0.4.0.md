# 0.4.0 ships: the CI is green, the scope changed, and three things are gone

- **Date:** 2026-10-27
- **Type:** release
- **Scope:** `ci`, `tooling`, `docs`

[中文版](2026-10-27-release-0.4.0.zh.md)

0.4.0 can be published at last. This entry records three things: the packages moved from `@jiumate` to `@jadelau`; three things the release could not have — a domain, an Alibaba Cloud OSS mirror, and signing certificates — are gone rather than faked; and the fact that the CI had never been green once since the repository opened, which took more work to fix than anything else here.

## The scope changed

`@jiumate` is taken on npm by somebody else, so the thirty-one packages moved to `@jadelau`. npm does not let a published name change, so this is not a redirect: it is a rewrite of every place a package name is written. Each `package.json`'s `name`, every `import` and type specifier, every `workspace:*` dependency edge, the `pnpm --filter` selectors in CI and in the release workflow, the install scripts' one-line install advice, and the Trusted Publisher checklist.

Two things in the source look like the scope and are not, and the rename script is careful about both. `@jiumate-builtin` is the suffix on a plugin id — the plugin library is addressed by it, so it stays. `~/.jiumate` is the data root and `jiumate/` is the repository; neither is a package name.

The rename script stayed in the repository, as `scripts/rename-npm-scope.mjs`. The next time this project needs a different scope is the same walk over the same files, and doing it by hand is how a name gets missed in one place.

## Three things that are gone

**The Alibaba Cloud OSS mirror.** The GitHub Release is the only distribution point now: the installers and the download manifest are uploaded to it, and `install.sh` downloads from it. The mirror's code stays in the scripts — a deploy that has one sets `JIUMATE_DOWNLOAD_SOURCE=auto` and it is used again, with GitHub as the fallback it always was. The default is `github` rather than `auto`, because `auto` would spend a round trip discovering that the mirror is not there.

**The installers are unsigned.** Signing needs an Apple Developer ID and a Windows EVSign account, and this release has neither. The signing steps in the desktop workflow already fall back to an unsigned build when they are not required, so the two flags now say false and the artifacts are published unverified.

**The domain.** The site is served from the repository's GitHub Pages address, so the deploy subpath is `/jiumate/` rather than the domain root, and every link that has to be absolute follows: the canonical URLs, the sitemap, robots.txt, the one-line installer commands, and the app's own attribution header. The origin and the subpath are separate values, because a domain is served from the root and Pages from a subpath, and the two change independently — bound together they write a doubled path. The site's `install.sh` and `install.ps1` are thin forwarders that download from GitHub Releases, so the install command never needed the domain to resolve; it only needed a stable address to paste.

`APP_URL`, the attribution the harness stamps onto an OAuth key, points at the repository rather than a marketing domain: it is an identifier that has to stay the same across releases, and it should point at where the software is.

## The CI had never been green

Every workflow run in this repository failed. From 2026-09-17 every job died within one to nine seconds with the same message about the account's spending limit, which covered up the real cause. Once the limit was fixed, the gates showed themselves, and there were eight:

- **Prettier** had never been run: 187 files did not match the format, and one of them — the installer's renderer — had a `div` left unclosed inside a section, so Prettier could not even parse it.
- **typecheck** failed on one line: `writeInspirationCase`'s `meta` declared `updatedAt` as a `string`, while the schema declares `string | null`, and a preset is written with none.
- **oxlint** failed on three files that import the same module twice, which is exactly what the rule was added for.
- **The license gate** failed on the docx editor's font package: its license is `Apache-2.0 AND OFL-1.1 AND LicenseRef-GUST-Font-License`, and the last of those has no SPDX identifier — it is the GUST Font License, whose operative terms are the LaTeX Project Public License 1.3c. All three are permissive, and the obligations of the two font licenses attach to the font file rather than to the work that embeds it.
- **The test gate** failed on the server shards, and that was the expensive one: 108 test files never loaded, because the shards built core's dependency tree and tested server. Server depends on pets, inspirations and skins; core does not, so those three were never built and the suite could not resolve `@jadelau/pets` before it ran a single test. Every shard that tests server now builds server's tree.
- **Playwright's browser** was not installed, so the five login-figure suites failed at `browserType.launch` with "Executable doesn't exist" — a message that reads like a broken test rather than a missing browser.
- **The POSIX launcher** was committed without the executable bit, so the installer test's `[ -x ]` check failed and the POSIX installer suite never ran.
- **The Windows installer suite** inherited the download source from the environment instead of pinning it per case, so every case that did not set the variable itself ran against whatever the installer's default happened to be.

**That last one was my own doing**, and it is worth writing down: after the default download source moved from `auto` to `github` — because the mirror is gone — the suite reported "canonical made 2 requests, expected 3". It had made the right two: those cases are about which source the installer picks, and the default is not what they are about. Each case now names the mode it is about, the way the POSIX suite already did.

Two more tests depend on POSIX signals. Ctrl-C has to reach a child in a pipeline, and a stop has to be a signal rather than an exit code, or the session cannot tell a stop from a failure. Windows has neither, so those two are skipped there — the twenty-odd Windows guards in this repository's other tests work the same way.

## What to look at after the domain changed

The site's deploy subpath went from `/` to `/jiumate/`, so the asset paths, the canonical URLs, the sitemap and the Open Graph image all moved with it. The domain and the subpath are two separate values now (`SITE_ORIGIN` and `BASE_PATH`), because they change independently.

## Compatibility

- **The package names on npm changed**: `npm install @jiumate/core` stops resolving and `@jadelau/core` starts. The old names were never published, so nothing needs unpublishing and no version needs deprecating.
- **Import paths inside the repository** changed with the names; no source outside the repository is affected.
- **The installers are unsigned**: macOS and Windows will say the app is from an unidentified developer.
- **There is one download source**: the mirror is gone and `install.sh` downloads from the GitHub Release.
- **The site's address changed**: `https://qiaiqian67.github.io/jiumate/`.
