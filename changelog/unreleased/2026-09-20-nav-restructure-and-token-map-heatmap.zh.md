# 重构侧栏、重命名四个门面，并重做词元图的全年热力图

- **日期：** 2026-09-20
- **类型：** feature
- **范围：** `web`、`core`

[English](2026-09-20-nav-restructure-and-token-map-heatmap.md)

侧栏的页面组现在是 智能体 / 插件·技能 / 灵感库 / 词元图，按此顺序。两个条目离开了它、去了更合适
的位置，四个门面改了名，词元图换上了产品参考图那套排布的全年热力图。另外改了两个偏好默认值，并
调整了模型目录的策展顺序。

## 导航只剩四项，两个页面是搬家而非消失

- **评估中心**不再有导航条目。它的页面、路由（`/benchmark`）与服务端路由都原样保留，深链依然可用。
- **模型库**迁入系统设置，位于「个人 → 模型」，与用户自己的其余配置放在一起。它渲染的就是 `/models`
  路由所用的同一个组件。
- 两个页面登记在新的 `NAV_UNLISTED_PAGE_KEYS` 里，于是 `NAV_ROUTES` 保持完备，重新上架只是两个数组
  之间搬一次，而不必恢复被删掉的代码。单测对这份名单做了断言——这正是防止日后有人把路由连同那一行
  一起删掉的那道锁。
- `navKeysFor` 去掉了 `isAdmin` 参数。它原本只为隐藏 `machines`，而后者现在是彻底不上架，所以导航不再
  因查看者而变；需要管理员权限的门面是系统设置里的服务器页，它们在 `settings-sections.ts` 里各自带着
  规则。
- 折叠态的窄栏跟随同一顺序，并随侧栏一起去掉了那两个条目。

## 模型库，寄居在设置面板里

- `ModelsPage` 拆成了一个薄页面壳（持有 `useDocumentTitle` 与 `h-full overflow-y-auto p-4 md:p-6`
  容器）和一个 `ModelsPane`（模型库本身，根节点不带 class）。这两样外壳都不属于对话框面板：
  `useDocumentTitle` 会设置 `document.title` 且从不还原，内嵌副本会在对话框关闭后把「模型库 ·
  Linsight」留在标签页上；而第二个整高滚动容器套在对话框自己的滚动区里，会叠出两条滚动条和两份内边距。
- 面板的根节点保留为元素而非 Fragment，因为它打开的对话框（新增分组、模型、OAuth、两个确认框）是它
  内容包裹层的兄弟节点——去掉根节点会把它们从返回值里摘出去。
- 设置里新增 `models` 页，归入「个人」分组，始终可见（它属于每用户配置），图标沿用导航条目原本用的
  那个。

## 四个门面改名

| 原名 | 现名 | 范围 |
| --- | --- | --- |
| 应用中心 | 灵感库 | 导航条目、页面标题 |
| 插件库 | 插件·技能 | 导航条目、页面标题，以及三条提到该库的错误文案 |
| 成本中心 | 词元图 | 导航条目、页面标题，以及两条提到它的快速模式提示 |
| 新建对话 / 新对话 | 新会话 | 导航区块的标签，以及「创建会话」这个动作 |

英文词典同步跟进：App Center → Inspiration，Plugin library → Plugins & Skills，Cost Center →
Token Map，New chat → New session。定时任务页自己的「新建会话」（指任务的落点）**刻意不动**——那句话
说的是任务创建一个会话，与这个控件无关。

## 词元图的全年热力图

- 面板按产品参考图重做：**列是周、行是星期**，月份标签骑在列的上方，五档图例在网格下方，右侧是三项
  头部指标——累计词元量（全年总数）、单日峰值（用量最高的那天）、活跃天数（有用量的天数）。悬停某一天
  显示日期、词元量与缓存命中率。
- 上一版是月份在侧、日期在横。那对「哪几个月重」很好读，但每个短月都会浪费掉 31 宽行里的大半，而且
  完全答不了「工作日还是周末」。
- 格子按**词元**着色（这是词元图，面板也来自「模型消耗…热力图」），同时 tooltip 用共享的 `cacheHitRate`
  报出当天的缓存命中率，两处不会各自漂移。
- 配色按**有用量那天的分位数**，而不是最大值的比例。Token 用量是尖刺状的——一次长任务可以比平常高一个
  数量级——按最大值取比例会把全年几乎都涂成最浅一档、只把那一根尖刺涂成最深，恰好与「有用」相反。
- 几何逻辑放在不含 React 的纯模块 `token-heatmap.ts` 里，与包内惯例一致——这里的 vitest 是 node 环境，
  纯函数才是测试能直接钉住的东西。它的 20 条测试覆盖闰年规则、首尾两周的补齐格、月份标记，以及那条
  「错位网格必然违反」的不变量：**每个格子的行号等于它自己的星期**。
- 面板自带请求。它**不**受页面日期区间约束（一年视图套在七天筛选下大半是空的），但**遵循** Agent 与
  模型筛选，因为那两个决定「屏幕上是谁的用量」，一个忽略它们的热力图会和周围每张图表自相矛盾。年份可翻，
  所以一月打开时依然有用。

## 两个偏好默认值

- **字号**默认改为 小（原为 中）。字号是偏好，而更大的两档本该是用户自己回来选的——默认取中间，等于让
  每个从没打开过「外观」的人都在读一个自己没选过的尺寸。
- **币种**默认改为 人民币（原为 美元）。价格始终以「美元/百万 Token」存储、仅在显示时换算，所以这只
  改变用户第一眼看到哪个数字——而目录里好几个网关组的预置价本来就是按人民币报的。
- 两者都接受可注入的 storage，让 Node 测试能触达，与 `initialNavGroupCollapsed` 同形。这在这里尤其重要，
  因为**错误的默认值在截图里看不出来**：停在中间档的界面和本该如此的界面一模一样，用美元显示的价格也
  就是价格。已存的偏好永远优先——包括恰好等于旧默认值的那种——因为它们决定的是**未被动过的**安装显示
  什么。

## 模型目录的策展顺序变了

- **TokenDance 从队首移到真实平台的末尾**，**DeepSeek 接手 `recommended`**。它紧挨 `custom` 之前，
  而后者被测试钉死为永远最后——它是用户自定义模型的伪平台，不是一个厂商。
- 「排在默认顺序首位」和「被标记为推荐」是同一个条目，有两处依赖的是这个事实而不是那个标志位：
  `defaultExpandedProviders` 展开下标 0 的那组，模型页给带 `recommended` 的条目加标签。两者仍然一致。
- web 测试套件读 core 走的是 **pnpm 注入到 `node_modules/.pnpm` 的副本**，不是 `packages/core`。所以
  源码改动在**通过 pnpm 构建 core** 之前对它不可见（`pnpm --filter @prismshadow/linsight-core build`，
  也就是 `dev-prebuild.mjs` 跑的那条）——`npx tsup` 只写 `packages/core/dist`，不触发同步钩子，于是 web
  测试继续断言旧顺序并且**通过**。正是这个假绿暴露了 `model-grouping.test.ts` 与
  `model-group-expansion.test.ts` 里的两条顺序断言。

## 内嵌的模型面板拿到对话框的完整宽度

- 模型页是全应用最密的页面：一个分组头里装着 logo、厂商名、模型计数、推荐胶囊和最多四个操作按钮，
  其中四项被 `@container` 断点挡在后面，从 `@lg`（512px）一路到 `@4xl`（896px）。寄居在系统设置里时
  它拿到的是默认 `sm:max-w-3xl` 减去侧栏与内边距——**531px 的内容列**，低于所有这些门槛里最低的那个，
  于是推荐胶囊成了唯一还活着的附加标记。
- `PagedDialog` 新增可选 `widthClass`，设置对话框**只为模型面板**传 `sm:max-w-5xl`。对话框是 portal 到
  `body` 的，所以它受**视口**限制而非应用主内容列；这一改动解掉对话框自身的上限，让面板吃掉窗口实际
  给得出的宽度（837px 视口下约 574px 内容列，视口更宽则更多）。其余设置页保持默认。
- **分组头从来就不是坏的。** 我先前把第 1154 行 `@xl` 那道门槛当成了厂商名，据此得出「分组头只剩光秃
  秃箭头」的结论。在那里隐藏的是**模型计数**；logo 与厂商名没有任何 `hidden` 类，是这一行里永远渲染的
  两样东西。这份宽度对密集页面是真实改善，而不是修缺陷——这一点必须写清楚，因为错误版本的说明会让
  后来的人去找一个并不存在的 bug。

## 中文汉化：Project 与项目角色

- 中文词典里 `Project` 全量改为 项目，含页面与对话框标题、轨迹导入文案、以及各条错误文案。文件头一直
  把 Project 列在「应译为中文的门面标签」之中，这次补上了这个缺口。
- 删除禁止提示里的字面 id `default_project` → 默认项目。
- 项目级角色：`owner` → 管理员（与用户管理页既有的服务器级角色标签一致），`member` → 成员，出现在三条
  只读提示里。同一句中的 `credential` 按同一规则改为 凭证——只有 Token 与 Agent 保留英文原词。

## 切换器给内置项目一个名称，徽章给角色一个中文

这两处字符串来自服务端数据而非词典，所以上面那一轮汉化漏掉了它们——直到截图里露出来：

- 侧栏的项目切换器显示 **`default_project`**——一个标识符，出现在用户最期待看到名称的位置。管理员的内置
  项目在创建时**没有**写入显示名（服务端只 insert 了 id/owner/createdAt，而非管理员的那份会写入用户名），
  于是 `projectDisplayName` 一路回退到了原始 id。现在回退到 **默认项目**。
  这是**标签**而不是写进数据的 `name`：名称是所有者可编辑的数据，在注册时写入会把当时那个安装的语言
  永久冻进存储。
- 旁边的角色徽章把 **`owner`** / **`member`** 原样显示。现在走 `projectRoleLabel`，得到 管理员 / 成员——
  与服务器级管理员用同一个词，两个作用域不会读起来像两种不同的权限。
- `DEFAULT_PROJECT_ID` 在 `state/project.tsx` 有了唯一的家。它没法从 core 引：`paths.ts` 引入
  `node:os`/`node:path`，而 core 的子路径导出恰恰是为「web 安全、无依赖」的模块准备的，从这里引会把 Node
  内建拖进浏览器包。这个字面量原本已在 `project-dialogs.tsx`（id 比较）和 `admin-users-page.tsx`
  （拼 `<username>-default_project`）里各写了一遍；两处现在都读这个常量，并由一条测试钉住它与服务端
  拼写一致——那是把两者绑在一起的唯一东西。
- 空字符串按「未设置」处理（`name: ""` 也走回退），因为 `project_config.toml` 可能带着空名称，而一行空白的
  切换器比任何一种回退都糟。所有者设过的名称仍然优先，包括在内置项目上——标签是回退，不是覆盖。
