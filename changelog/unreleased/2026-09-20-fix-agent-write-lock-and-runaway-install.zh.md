# 文件被占用时重试写入，并阻止一次运行把十几分钟耗在装浏览器上

- **日期：** 2026-09-20
- **类型：** 修复
- **范围：** `core`

[English](2026-09-20-fix-agent-write-lock-and-runaway-install.md)

解析一次真实会话的轨迹（智能体被要求做一个 HTML 看板）后发现：全程 18.5 分钟，其中模型推理 3.7 分钟、工具执行 14.6 分钟。而这 14.6 分钟里有 13 分钟耗在一条自己走出来的弯路上——智能体认为需要用 Playwright 给自己写的页面截图，于是装了 Playwright 和 Chromium，然后**六次无进展地轮询下载**，最后把它杀掉。此外它 16 次 `edit_file` 里有 3 次直接失败。两个问题都在 Harness 侧，本次一并修掉。

## 文件被占用不再导致写入失败

- `atomicWriteFile` 的替换方式是「写临时文件 → rename 覆盖目标」，而这个 rename **没有任何重试**。Windows 上，只要目标文件被其他进程持有，`rename` 就返回一个裸的 `EPERM`——正在扫描刚写入文件的杀毒软件、搜索索引器，或者用户正用来查看该页面的浏览器都会造成这种情况。这个错误和真正的权限问题无法区分，于是**一次瞬时占用就变成一次工具调用失败加一次白跑的模型往返**。在解析的那次会话里，它命中了 16 次 `edit_file` 中的 3 次，而触发条件恰恰就是用户自己的用法（写页面、打开看、再让它改）。
- 现在 rename 会针对 `EPERM` / `EBUSY` / `EACCES` 做**有界退避重试**，总时长不到一秒。超过这个预算仍未拿到的锁不是瞬时占用——而是有进程以独占方式持有该文件，等多久都没用——所以此时快速失败，并给出**指明原因、且说明文件未被改动**的错误，而不是抛回一个看起来像 `chmod` 问题的 `EPERM`。
- 重试放在 `atomicWriteFile` 内部，因此它的九个调用方全部受益：`edit_file`、`write_file`、项目配置、智能体状态、vault 和内核更新。

## 中文命令输出重新可读

- 命令会话按 UTF-8 解码 stdout，但 Windows PowerShell 用的是控制台 OEM 代码页——中文系统上是 GBK。于是命令回显的每个中文路径和消息都是乱码（`目录` 变 `Ŀ¼`，`数据来源` 变 `������Դ`），模型读不回自己刚写的内容。这也是它转向「截图验证」的原因之一。
- `ShellInvocation` 新增 `preamble`，在 spawn 时拼接到命令串前面。对 PowerShell 它同时设置 `[Console]::OutputEncoding` **和** `$OutputEncoding`，这两个是不同的开关：前者管 PowerShell 自己写出的内容，后者管它交给原生命令的内容。两个都设上，也顺带修好了 `node` / `git` / `curl` 的输出——因为 PowerShell 用的就是同一个设置去解码原生命令的输出。反过来「把管道按 GBK 解码」只会修好 PowerShell 自身的排版，却会毁掉每个输出 UTF-8 的原生命令。
- `cmd.exe` 用 `chcp 65001`（部分修复——只管 cmd 自己的输出）。POSIX shell 本来就是 UTF-8，不加任何东西。
- preamble 在 spawn 处拼接，**不写进存储的命令**，所以审批弹窗和完成报告里仍然是用户写的那条命令。

## 提示词不再鼓励装浏览器

- `DEFAULT_SYSTEM_PROMPT` 原本写着「装了 Playwright 就优先用它」，但完全没提代价。智能体把这条偏好读成了「去装它」。现在明确写了不要为了满足这条偏好而安装，并说明 `curl` 加读标记就足以检查你自己写的页面。
- 新增约束：用户没要求就不要安装依赖；`npx <pkg>` 在包缺失时会**自动安装**（要表达「只在已装时使用」请写 `npx --no-install`）；浏览器或测试框架可能是几百 MB 和好几分钟。
- 新增工具使用规则，每一条都来自那次轨迹：能跑上几分钟的命令用 `run_in_background` 启动，而不是放前台轮询（每次 `input_command` 轮询都会**等满**它自己的 `yield_time_ms`）；不要把长命令管道接给「只能在结束时才输出」的过滤器（`| Select-Object -Last 5`、`| tail -5`），它会把每一行都压到进程退出才吐，使正常下载和卡死看起来一模一样；同一处改动在一份文件里重复出现时，用 `replace_all` 或一条 shell 命令一次改完，而不是每处一次调用。

## 内核推进到 2026-09-20

- prompt 和 tools 两个 tab 都发生了移动：tools 是因为上一轮的桌宠替换把 companion 工具换成了单个 `pet` 工具**却没有推进内核**，导致钉住的哈希守卫一直是红的；prompt 则是因为上面的提示词改动。被取代的哈希记录已追加旧值，前开关时代的重建值也重新锚定。

## 测试

- `packages/core` 覆盖「占用会解除」（写入成功）和「占用不解除」（错误指明原因、旧内容保留、不留临时文件）两种情况。仅 Windows 运行，因为这个条件本身只存在于 Windows——POSIX 上 rename 一个被打开的文件是成功的。
- `packages/core` 端到端覆盖 preamble：一次真实 spawn 证明 GBK 的 PowerShell 输出变成可读 UTF-8，另一次证明退出码和原生命令的 stderr 未受影响。
- `packages/cli` 在 tsup 覆盖清单里补上 `pets` 和 `skins`。
