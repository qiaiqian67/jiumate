# 插件卡片有了真正的启用开关，以及输入 API key 的地方

- **Date:** 2026-10-12
- **Type:** feature
- **Scope:** `web`

[English](2026-10-12-plugin-card-switch-and-credentials.md)

插件页签上有两处东西只提问、不给答案：只要插件需要凭据，卡片就画一个钥匙图标；启用开关则是一个电源图标——两者都是标记，都不可编辑。这次改动让卡片带上一个余光可读的控件，并给钥匙一个落脚处。

## 卡片上的操作

- **按钮更小。** 角落那一组从五个 32px 方块变为 28px，间距也收紧。在三列网格里卡片是页面的三分之一，于是这一组在与插件名争夺同一行，名字在约十五个字符处就截断了。图标本身保持原尺寸：15px 落在 28px 按钮里仍读作图标而不是一个斑点；而仅为一张卡片往图标尺寸表里加一档，会让表里多出一个别处无人共用的尺寸。
- **启用／禁用是一个 `Switch`。** 它替换了电源图标而不是加入那一排，而这正是要点。在那四个图标里，电源标记是唯一一个状态寄寓于图标本身而非其形状的——填充与描边的差别没人能一眼读出——而旋钮在轨道的一端或另一端，无需悬停就自陈其状态。它也让这个开关不必去争已被其余图标填满的第四个方块。
- **`Switch` 新增 `sm` 尺寸**（28×16 轨道配 12px 旋钮）。组件默认的 36×20 是为带标签的表单行调的，如今它要与 28px 的按钮同行，会比每一个邻居都高。旋钮与行程一同缩放，因此缩小盒子不可能让旋钮越过轨道的端帽——两种尺寸下，净间隙在四周都保持均匀的 1px。

## 详情视图里的 API key

卡片的钥匙图标只回答「这个插件配置好了吗」，仅此而已，于是「钥匙该放哪」指向了 Agent 设置页——另一个屏幕上的一枚齿轮图标，而用户正看着那个需要钥匙的东西。详情弹窗现在自带输入处。

- **每个声明的变量一个密码框**，位置在统计行与文件浏览器之间：那屏上其余一切都在描述插件带来什么，而一个声明出来的凭据是其中唯一有时需要用户动手做的事。
- **变量在各技能之间收集、去重并排序。** 一个插件里的两个技能可能声明同一个服务商的密钥，这一节只问一次——两个输入框绑同一个键名，会让第二次保存悄悄覆盖第一次。
- **写入所选 Agent 的保险柜**，而它本就是让一个 shell 变量抵达该 Agent 的 `exec_command` 子进程的机制；Agent 设置里的保险柜页签就是同一次写入。`required_env` 这个名字*就是*一个 shell 变量——Firecrawl 技能自己的 `curl` 就是从 shell 里调用 `$FIRECRAWL_API_KEY` 的——因此写到别处只会造出第二份看不见的副本，而运行时根本不读它。
- **点名是哪一个 Agent，而不是假定。** 设在某个 Agent 上的密钥不会抵达另一个，而弹窗打开时没有选中 Agent 的次数与选中时一样多，所以这一节会说明它写入哪个 Agent，并在没有 Agent 时直说。写错 Agent 的凭据是静默失败：录入它的那张卡片读起来是已配置，而需要它的技能仍然报告密钥缺失。
- **值永不回传**，因此已配置的密钥显示为带「已配置，留空表示不修改」占位符的空输入框；保存其中一个时会把其余每一条按键名单独重发。保险柜的 PUT 是整表替换，只发送被改的那一个键会静默删掉该 Agent 的其他凭据。
- **成员看到的是被禁用的输入框，而不是被隐藏的输入框。** 保险柜写入在服务端仅限所有者，而看着这张卡片的成员需要知道这个密钥存在，且设置它需要另一个角色。
- **保存后钥匙图标从服务端重新读取**，因为 `requiredEnvReady` 是每次请求实时解析而非缓存的，卡片应当依据那个答案变绿，而不是依据对这次写入做了什么的假设。

一个不声明任何变量的插件完全不渲染这一节——在一个本无密钥可配的插件上放一个空的「API 密钥」框，会暗示有什么东西没配好。
